How it works

Three steps, fully authenticated

Every upload runs a fresh cryptographic handshake, so no key or keystream is ever reused.

1

Key exchange

A fresh ephemeral X25519 key pair performs Diffie–Hellman with the receiver to derive a unique shared secret — no key is ever transmitted or reused.

2

Encrypt

HKDF-SHA256 expands the secret into a 256-bit key and the file is sealed with AES-256-GCM under a random nonce. Nothing is stored in plaintext.

3

Verify

A SHA-256 fingerprint and the GCM authentication tag detect any tampering the instant a file is downloaded.

The stack

Built on modern primitives

X25519 ECDH

Elliptic-curve Diffie–Hellman derives a fresh shared secret for every single file.

AES-256-GCM

Authenticated encryption (AEAD) protects confidentiality and detects tampering.

HKDF-SHA256

The shared secret is expanded into a strong 256-bit key with a random per-file salt.

SHA-256 Integrity

Every stored file is fingerprinted so any change is detected on retrieval.

Argon2 Passwords

Credentials are stored with a memory-hard hash that resists brute-force and GPUs.

Guarantees

What every transfer protects

Confidentiality

Files are encrypted with AES-256-GCM; the server never stores readable content.

Integrity & tamper-detection

GCM auth tags plus SHA-256 digests reveal any modification immediately.

No key or nonce reuse

Every upload uses a fresh ephemeral key, HKDF salt and GCM nonce.

Hardened credentials

Passwords are Argon2-hashed and every action is access-controlled per owner.
